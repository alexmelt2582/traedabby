# Handoff: TRAE SOLO CN Enhancer

## Current state

This repository is a local, non-invasive enhancement assistant for `TRAE SOLO CN`
on Windows. It injects a panel into the running Electron renderer through CDP and
keeps account authentication snapshots on the local machine.

Implemented and user-confirmed:

- CDP-based UI injection with account backup, account switching, seamless OAuth
  login, and traditional fake-logout login.
- Transactional account switching: refresh the target token, stop TRAE precisely,
  replace only authentication keys, restart, verify identity, and roll back on
  failure.
- Seamless login: browser OAuth without closing TRAE.
- Fake logout: back up the current account, preserve non-authentication state,
  reopen TRAE at the login page, detect the new identity, save it, and restore the
  original account on cancel, timeout, or failure.
- Interrupted fake logout recovery: the active session is persisted under
  `data/fake-logout/session.json`; a restarted daemon can complete new-account
  detection or roll back to the original account.
- Encrypted import/export: selected accounts are exported with `gzip`,
  `AES-256-GCM`, and `scrypt`. Imports validate and decrypt the file, deduplicate by
  stable identity, update existing backups, and add new accounts without switching
  the current login.
- Cold start through `scripts/start.cmd` was verified by the user with TRAE fully
  closed. The current TRAE session was started through that script.
- Account operation rollback no longer writes `storage.before.json`, and startup
  removes the legacy `data/transactions/` directory.
- Sentinel account emails such as `unknown` are normalized to `null` in the index
  and cleaned from stored authentication snapshots.
- Seamless OAuth and fake logout are mutually exclusive at the daemon API level,
  including the concurrent-start window before a session is registered.
- Atomic JSON/text writes in `src/lib/json-file.js` are now serialized per target
  path and retry transient Windows rename failures (`EPERM`, `EACCES`, `EBUSY`).
  Before this, two concurrent writers to the same path (for example `cancel()`
  persisting `session.json` while the run loop persisted the same file) could fail
  the `fs.rename` with `EPERM`. That aborted `restoreOriginal` at its first state
  write, so `stopTrae`, `applyAuthSnapshot`, and `startTrae` never ran and the
  account was left with cleared authentication keys.
- New `test/json-file.test.js` covers concurrent same-path writes, call-order
  application, transient-rename retry, and non-transient error propagation.
- The panel is now version `1.0.0`, uses fixed dimensions with Account and About
  tabs, and follows the WorkDaddy-style account summary/card layout.
- Account cards show phone, plan, and remaining credits for every saved account.
  The real Trae v2 `ide_user_ent_usage` API supplies `usage_summary` and
  `credits_limit` data; do not replace this with the v1 fast-request fields.
- Automatic daily check-in is implemented, user-confirmed, and committed.
  The daemon runs once five seconds after startup and then every 30 minutes. Each
  account uses its own stable `userId` as `x-device-id`, and the status/claim calls
  are pinned to `https://api.trae.cn`, matching the working Cockpit endpoint.
  This avoids the shared-device-id collision where only the first account could
  check in.
- Account cards expose `已签到`, `待签到`, or `失败`; the Account toolbar includes
  an immediate check-in button, and the About tab lists automatic check-in.
- Live verification on `2026-09-14`: all 3 saved accounts checked in automatically,
  each received the full 150-credit reward (`extra_credits: 50` is only the extra
  component, not the total), a second manual run skipped all 3 accounts as
  already checked, and account insight refresh completed for all 3.
- Automatic account keep-alive is implemented but not yet committed or user-confirmed.
  It sweeps every 30 minutes and keeps each inactive account on a six-hour refresh
  interval. Inactive snapshots rotate login credentials and refresh usage data.
  The active account is backed up from the running TRAE storage and its usage is
  refreshed without rotating the live refresh token. Failures retry after 30 minutes.
  The sweep is skipped while Cockpit Tools is running.
- Live verification on `2026-09-14`: two inactive accounts rotated credentials and
  updated usage successfully; the active account synchronized from live storage
  without token rotation. The panel displayed `正常`, `正常`, and `运行中`.

Important code facts:

- Login state is read from
  `%APPDATA%\TRAE SOLO CN\User\globalStorage\storage.json`.
- The authoritative login key is `iCubeAuthInfo://icube.cloudide`.
- A complete snapshot also needs the matching `iCubeAuthInfo://icube-dc:*`
  device key, `iCubeAuthInfo://usertag`, and `iCubeServerData://*`.
- Entitlement data may be either a standalone
  `iCubeEntitlementInfo://icube.cloudide` key or embedded as `entitlementInfo`
  inside `iCubeServerData://icube.cloudide`. Both forms must remain supported.
- Do not write `state.vscdb` for account switching. The current Trae version
  restores iCube login state from `storage.json`.
- Non-authentication keys such as workspaces, settings, extensions, and window
  state must always be preserved.
- Atomic file writes must stay serialized per target path and must retry transient
  `EPERM`, `EACCES`, and `EBUSY` rename failures. On Windows two concurrent
  `MoveFileEx(..., MOVEFILE_REPLACE_EXISTING)` calls onto the same destination can
  fail intermittently even when both writers are in the same process.

## Working commands

This Codex environment keeps Git metadata in `.git-meta` because the standard
`.git` directory has been read-only for the command executor:

```powershell
git --git-dir=.git-meta --work-tree=. status --short
git --git-dir=.git-meta --work-tree=. log --oneline -5
npm test
npm run check
node src/launcher.js
```

Health check:

```powershell
Invoke-RestMethod http://127.0.0.1:47834/api/health
```

Authenticated local API calls need the token from `data/api-token`. Never print or
log the token value.

Restarting the daemon after source changes may require stopping the exact daemon
PID reported by `/api/health`, then running `node src/launcher.js` again. Do not
kill all Node or Electron processes.

## Safety boundaries

- Bind services to `127.0.0.1` only.
- Never log or expose access tokens, refresh tokens, cookies, private keys,
  passwords, or complete authentication snapshots.
- Do not modify the official TRAE installation or `app.asar`.
- Only manage processes whose executable path matches the configured TRAE SOLO CN
  installation.
- Do not run Cockpit Tools and this assistant's automatic token refresh flow at
  the same time. They can rotate each other's refresh tokens.
- Import/export files are encrypted. Never add a plaintext export fallback.
- Use UTF-8 without BOM for source and JSON files. Keep `.cmd` files ASCII/CRLF.
