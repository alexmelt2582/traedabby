# TRAE SOLO CN 增强助手 v1.3.0

发布日期：2026-09-30  
发布类型：正式版（功能更新）  
签名状态：未签名，Windows SmartScreen 可能提示未知发布者  
网络：新增代理配置（直连 / 跟随系统 / 自定义），默认直连。

## 本次更新

- 新增代理配置，在设置页「网络」里选择：直连、跟随 Windows 系统代理、或自定义代理地址。支持 HTTP、HTTPS、SOCKS5，可填代理账号密码与「例外地址」（这些域名不走代理）。
- 保存后立即生效，不需要重启后台服务；配置写在本机 `data/config.json`，不出这台机器。
- 新增「测试连接」：先直连探一次、再走代理探一次，最后只给一条结论，并说明下一步该做什么。
- 命令行新增 `configure --proxy-*` 与 `net` 诊断；面板的测试连接与它共用同一套判定，不会出现两处结论不一致。
- 新增「信任 Windows 证书存储中的根证书」（默认开启），供内网自签证书的代理使用。不采用关闭证书校验的做法。
- 代理账号密码按需求明文保存在本机 `data/config.json`；它们不会出现在日志里，也不会出现在面板读取的设置接口里。
- 修复旧版本遗留的 `config.json` 会让整个程序失效的问题：旧格式（`proxy.mode` 为 `manual` / `env`）以前会导致所有命令都以退出码 1 结束，现在打开时自动迁移——`manual` 转成自定义代理并保留原地址，`env` 转成跟随系统代理。你在面板和命令行里输入的值仍然严格校验。
- 新增：命令行执行失败会写入 `logs/service.log`，包含完整原因且逐行脱敏。安装时如果提示「退出码 N」，可直接查这个文件，不再无从下手。
- 更正历史说明：v1.0.1 / v1.1.0 / v1.1.1 的发布说明中「完整代理实现保留在 feature/proxy-support 分支」一句已不适用——代理功能自本版本起正式随主分支发布。这三份已发布的说明保持原样不动。

## 已知限制

- 安装包未签名，Windows SmartScreen 可能提示风险。
- 更新检查只负责提示，不会自动下载或安装；升级仍需运行新版安装包。
- 导入导出属于账号迁移，不是多设备共享。原设备继续更新登录信息后，副本可能失效并需要重新登录。
- 手动续签会让同一账号在其他设备上的登录信息失效，仅在有意为之的场合使用。
- 代理认证只支持用户名 + 密码，暂不支持企业代理常用的 NTLM / Kerberos 认证。
- 命令行写入的代理设置需要重启后台服务后才生效；在面板里保存是立即生效。
- 代理账号密码在本机是明文存放（按需求如此），请不要把 `data/config.json` 外发。
- 当前仅支持 Windows 10/11 x64 和 `TRAE SOLO CN`。
